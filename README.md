# 亲手为自己造一本教材

> 写给不懂技术、想给自己（或孩子）造一本教材的人。装一次，之后每次造书都从「新开一个对话」开始。
>
> **任何能读技能目录的 AI 助手（agent）都能装**：这套东西是纯文本，一个文件夹拷进去就完事。Claude Code 是其中一种，也是今天唯一能用插件市场一条命令装上的那一种。

## 这是什么

你把手上的一本教材（或者一个想学的领域）交给你的 AI 助手，它按「读材料 → 定设计 → 先写一章给你看 → 铺完全书 → 终检」的路子，陪你把一本属于你自己的教材造出来。
成品默认是给 AI 苏格拉底老师上课用的**教学蓝本**，也可以选给人读的**流畅教材**，两条路线开工时二选一。
全程你只在三个关卡拍板——学习目标、章节板块、全书架构——查资料、写作、审计、返工这些重活由 AI 带着小助手干。

## 三分钟装起来

### 装之前，确认两件事

1. **你已经有一个能读技能目录的 AI 助手。** 判断标准只有一条：它认「技能目录」这个说法，能按目录名找到里面的 `SKILL.md`。Claude Code 是其中一种。
2. **电脑上有 Python 3**，而且能装一个叫 `requests` 的小库（造书第一步的 PDF 转换脚本要用它，见第二步）。

### 第一步：把整个文件夹放进 AI 助手的技能目录

**① 拷目录——任何 agent 都走这条。** 先 clone 下来，再把整个 `craft-your-textbook` 文件夹拷进**你这个 AI 助手的技能目录**：

```bash
git clone https://github.com/xx-hub/craft-your-textbook.git
mkdir -p <你的 AI 助手的技能目录>
cp -r craft-your-textbook/skills/craft-your-textbook <你的 AI 助手的技能目录>/
```

`SKILL.md` 是这个技能的唯一入口：整个文件夹放进去就算装好。
每家的技能目录名不一样，以那个助手自己的文档为准。最常遇到的一格是 **Claude Code 的 `~/.claude/skills/`**，把它填进上面那个尖括号即可：

```bash
cp -r craft-your-textbook/skills/craft-your-textbook ~/.claude/skills/
```

装完自查（这一行应当原样打印出一个以 `SKILL.md` 结尾的路径）：

```bash
ls <你的 AI 助手的技能目录>/craft-your-textbook/SKILL.md
```

**只想在某个项目里用（Claude Code 的项目级形态）**——放进项目自己的 `.claude/skills/`，只在这个项目里生效（`<项目>` 换成你的项目文件夹，写绝对路径最稳）：

```bash
mkdir -p <项目>/.claude/skills
cp -r craft-your-textbook/skills/craft-your-textbook <项目>/.claude/skills/
```

**想跟着仓库更新**——不重新拷，改用软链接（先 `cd` 到当初 clone 出来的那一层）：

```bash
ln -s "$(pwd)/craft-your-textbook/skills/craft-your-textbook" <你的 AI 助手的技能目录>/craft-your-textbook
```

一个位置只放一份：先 `cp` 过就先删掉那份，再建链接——两个同名目录不能共存。

**Windows**：上面的命令都在 **Git Bash** 里跑（`~` 会展开成你的用户目录）。

**下载压缩包也行**：在仓库页面点 `Code → Download ZIP`，解压后把 `skills/craft-your-textbook/` 整个文件夹放进技能目录。

> 验证情况（2026-11-04）：拷目录的三条命令、自查、项目级与软链接两段，都按组装好的产物跑通了；**真网址 clone 与 ZIP 两条没验过**（前者只验了地址可达，后者要图形界面）。逐条记录见开发仓里的维护规约（skill-maintenance.md，不随包发布）的「发布前实测台账」一节。

**② 插件市场——只有 Claude Code 支持这条**（在它里面直接敲）：

```
/plugin marketplace add xx-hub/craft-your-textbook
/plugin install craft-your-textbook@craft-your-textbook
```

> 验证情况：这两条**没跑过**——写这份说明的机器上没装 Claude Code。它们是插件市场的标准写法，装完效果与 ① 相同；除 Claude Code 之外的助手走 ①。

### 第二步：装 Python 依赖，拿一个 MinerU Token

造书第一步要把 PDF 转成文字，用的是技能自带的 Python 脚本，它只依赖一个库：

```bash
python3 -m pip install -r "$SKILL_DIR/scripts/requirements.txt"
```

`SKILL_DIR` 怎么定位，只有一处出处：装好后 `SKILL.md` 的「Phase 1 前置」那一节第一段的 `find` 命令——先在那里跑一遍，再回来跑这一行。

被 PEP 668 挡住时（系统 Python 不许 pip 直接装包）：先装 `python3-venv` 建虚拟环境、在里面重跑上面那条命令；还挡就用 `--break-system-packages`（**它真的动系统 Python**，在你自己机器上再决定）。`--user` 挡不住这条，不用试。完整的处置顺序见 `SKILL.md` 的「Phase 1 前置」那一节。

然后去 [MinerU](https://mineru.net) 拿一个 Token：

1. 打开 <https://mineru.net> 注册；
2. 申请一个 **API Token**，复制下来；
3. 在**你要启动 AI 助手的那个终端里**设成环境变量，再启动对话：

```bash
export MINERU_TOKEN="你的token"
```

（Windows 的 Git Bash 同样用 `export`；PowerShell 里是 `$env:MINERU_TOKEN="你的token"`。）

Token 只走环境变量：转换脚本只认 `MINERU_TOKEN` 这一个来源，缺了它会打印「✗ 未找到 MINERU_TOKEN 环境变量」并退出。

### 第三步：第一次对话说什么

新开一个对话，把材料在哪、想要什么书说清楚就行：

> 帮我造一本《人教版七年级上册英语》的教学蓝本。学生用书在 `/Users/你/教材/七上英语.pdf`，教师用书在 `/Users/你/教材/七上英语教师用书.pdf`。

（路径换成你电脑上的真实位置；Windows 上形如 `C:\Users\你\教材\七上英语.pdf`。）

AI 会先问你一件事：这本书是给 AI 老师上课用的**教学蓝本**（默认推荐），还是给人读的**流畅教材**？这是第一个岔路口，它一定会停下来等你选。

接着它会读材料，把重点难点和章节建议摆给你看，在三个关卡上等你拍板。你不需要懂技术，只需要回答「这样对不对、要不要改」——问路线、三个关卡、章节建议这套流程，都写在装好后的 `SKILL.md` 与 `references/` 里。

---

> ### 先看清它能承诺什么，不能承诺什么
>
> **能承诺**：造出来的书是 **AI 苏格拉底老师能直接拿去上课的教学蓝本**——有场景、有知识点、有提问路线、有弹药库，老师照着就能一步步引导；或者是一本**给人读的流畅教材**——正文是叙事，章末带练习和讨论题，AI 老师也能直接拿它教。两条路线在开工时自选。
>
> **不能承诺**：
>
> - **书的绝对质量**。它取决于两件你也参与的事：源材料有多好（有没有教师用书、材料全不全），以及你愿意陪它审几轮。材料越全、你越认真看，书越好；反过来，谁也不能保证一本「完美」的书。
> - **AI 老师的人设与上课效果**。老师是什么性格、怎么说话、课上得好不好，归 [Socratopia（破卷）](https://www.socratopia.app/r/SCR-FEJXMQ) 平台，不归这本书。
>
> 这两条是**边界**，不是免责套话：第一条决定你该花多少力气找材料、陪它审几轮；第二条决定你该去哪里调老师的性格。

## 方法论说明：为什么这样造书

### 书首先是给 AI 老师读的

无论哪条路线，AI 老师都会读完整本书作为上课的输入。所以书里每个字都要服务一件事：**AI 老师会怎么用它上课**。书对老师有四个用处：

1. **内容锚定**——防止老师跑题、编造；
2. **知识结构**——给出一条推理主线；
3. **弹药库**——案例、例题、词条随取随用；
4. **提问路线图**——用什么问题把学生引到知识点上。

最容易犯的根本错误，是把蓝本当纯文学作品写：开篇写一个「读者读到这里会想……」的钩子，通篇用「你」跟读者对话却不写清「你」指谁。AI 老师不需要钩子，只需要能拿来上课的东西。

### 两条路线，开工时选一条

- **教学蓝本**：只给「场景 ＋ 知识点 ＋ 提问路线图」，**绝不写死「老师说……学生答……」的对话脚本**——写死了 AI 老师会照抄，教学就死了。它必须为老师提供结构化的提问方向、问题链。
- **流畅教材**：正文是流畅的叙事，不内嵌给 AI 老师的元指令；每章末尾有结构化的教学素材区（练习、讨论题、教学脚本），那就是老师的提问路线图；合并成书时会在开头注入一段给老师看的说明。

两条路线互斥，默认推荐教学蓝本。

### 六个阶段

| 阶段 | 做什么 | 你在哪拍板 |
| --- | --- | --- |
| 一、源材料准备 | PDF 转成文字，材料理清楚 | — |
| 二、源探查 | 摸清材料结构、分清主次、标出谁是谁（学生用书／教师用书／考纲／讲义／真题），做事实校准 | — |
| 三、教学设计 | 分析材料 → 定路线 → 选章节板块 → 设计全书架构 | **三次拍板**：学习目标、章节板块、全书架构 |
| 四、金标准章 | 先按设计写一章，做到最好，跑完审计与试教 | 看这一章，确认风格 |
| 五、全量写作 | 按金标准并行铺其余章，逐章审计，最后跨章审计、合并成书 | 章节清单里随时看、随时提意见 |
| 六、交付 | 终检、拆掉所有造书过程留下的脚手架、逐项过交付前检查 | 最后认可一次，下载成品 |

**核心设计：不套模板。** 书的形状由 AI 根据你的材料和目标，从 **21 张模式卡**里选、混搭或新造，并在设计时回答两个问题——拒绝了哪些模式、为什么；所选模式对应什么教学问题。不变量是底线，模式库是菜单，四个必须回答的设计问题（书的元信息、章节骨架、写作规范、源材料索引）把设计逼到说清楚。你只需要在三个关卡上签字。

### 有教师用书，就能直接针对应试

造出来的书不只是「讲懂知识」，它可以直接服务于考试——这正是我们反复强调「务必要到教师用书」的原因。教师用书里藏着应试的全部密码：

- **评价标准与教学目标**——学完这一单元要做到什么、考到什么程度，就是命题的靶心；
- **学情分析与常见错误**——预判学生会在哪儿栽跟头，直接变成书里的误区桩和陷阱题；
- **考点与题型提示**——哪些是重点难点、常以什么题型考；
- **比学生用书深一层的讲解**——兜住正确答案，老师上考场不会讲错。

有了教师用书，AI 老师就不只是陪你学明白，而是带着明确的评价标准和考点意识，把你一步步引到考试要求的水平。这是单靠学生用书做不到的，也是「学生用书 ＋ 教师用书」被设为默认流程的根本原因。

### 质量靠什么守

- **四层审计 ＋ 试教**：每一章都过一个独立的审计小助手（上下文干净、不跟写手串通），金标准章还要试教；全书合并前再做一轮跨章审计；
- **交付前拆脚手架**：版本标记、自检清单、修订日志、「教师用书说……」这类造书过程的元数据，对只读一本书的 AI 老师零价值，交付前必须拆干净；
- **交付前检查 12 项全过**才允许交付，不以「接近全绿」放行；
- **多轮迭代是常态**：平均每本书 5–7 轮审校，不要期待一次成型。

### 适用面

任何学科——英语、语文、数学、物理、历史、编程、认证考试都能用。不预设板块骨架：语言类会启用词汇分层卡，理科和认证类会启用公式、判断题卡，叙事类会启用主角、贯穿案例卡。没有「按学科硬分」的表格，只有「按教学问题选模式」。

这套方法靠**派子代理**干重活：精读每份材料、写作、章级审计、跨材料对齐、图的审校，各是一个独立的小助手。**没有子代理调度能力的 AI 助手照样能装**，只是会退化成一个人在同一个上下文里跑完全流程——慢，而且上下文越长越容易漂。

### 这份方法背后的信念

如果「人本具足」是真的——每个人内在本就具备通往知识的能力，教育的本分是把它引出来而不是填进去——那么教育就该从「灌输」走向「引导」。可过去做不到，因为**引导是昂贵的**：一个学生每天学 8 小时，就要一位老师全职陪 8 小时，还得备课。于是绝大多数教学只能是灌输式的：一个老师对着几十个学生讲。不是不想引导，是引导不起。

AI 第一次让另一种范式成为可能，因为它提供了三件过去买不起的东西：**完全定制化的私人教材**、**全天候无限精力的私人教师**、**最适合你的引导方法**。而这条路最基础的一块砖，就是把一份素材加工成「AI 老师能沿主线教学、不跑题、不幻觉」的书——这正是这个 skill 做的事。
